Deep Dive Concepts

Query Modifiers (Projection, Sort, Skip, Limit)

The Plain-English Breakdown: Projection includes/excludes fields. Sort orders results. Skip bypasses documents. Limit restricts the count returned.

Real-World Use Case: Implementing pagination on a frontend (skip and limit) and hiding passwords (projection).

The "Gotcha" (Common Pitfalls): Execution order is ALWAYS: match -> sort -> skip -> limit -> project, regardless of the order you chain the methods in Node.js.

Memorization Hook: Order doesn't matter in code: Sort-Skip-Limit happens naturally.

Examiner: If I chain .limit(2).skip(5), what order does MongoDB execute them?
MongoDB always executes sort, then skip, then limit. So it will skip 5, then limit to 2.
Examiner: How do you exclude the _id field in projection?
You must explicitly set it to 0: { _id: 0 }. It is the only field included by default.
