Deep Dive Concepts

Ordered vs Unordered Inserts

The Plain-English Breakdown: When inserting many documents, ordered: true (default) stops on the first error. ordered: false attempts to insert all documents, ignoring individual failures like duplicate keys.

Real-World Use Case: Bulk importing logs where you want to skip duplicates but keep inserting the rest (ordered: false).

The "Gotcha" (Common Pitfalls): Even with ordered: false, if there's a syntax error, the whole operation fails. It only bypasses constraint errors (like duplicate _id).

Memorization Hook: Ordered = Stop on red light. Unordered = Run red lights.
